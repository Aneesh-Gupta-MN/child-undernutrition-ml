# Initial ML methodology plan

Prepared 29 October 2026. Planning document; no empirical findings.

## Research question

How well can eight questionnaire-derived variables estimate current stunting in eligible NFHS-5 children aged 6–59 months, and does a tree-based model improve on simple baselines under geographic validation?

## Data and cohort

Preferred source: approved India NFHS-5 (2019–21) Children's Recode, Stata release. The application also supports the supplied derived `india_kr.csv` extract. For the raw release, start with living children of interviewed mothers, age 6–59 months, with a usable WHO height-for-age outcome, and confirm residence/co-residence and measurement timing before freezing eligibility. This maternal-linked subset is not the full population of children encountered in outreach.

The derived CSV contains the eight predictors, HAZ outcome, state, PSU, stratum, and survey weight needed by the implemented experiment. It omits raw child and household identifiers, living status, mother co-residence, and a separate measurement-age field. For this input, the implemented cohort uses supplied children aged 6–59 months with plausible HAZ and keeps every child from a PSU in the same partition. The analysis cannot independently reconstruct the raw-release eligibility rules or household-level grouping; these limitations must appear in any report based on the extract.

For the original untransformed DHS recode, `hw70` stores height-for-age z-score multiplied by 100. The proposed label is valid HAZ below −2; special, missing or flagged outcomes must never become negatives. Confirm units and labels in the downloaded release. The first audit uses the project's proposed −6 to +6 validity range as a provisional quality check.

Predictors: `b19`, `b4`, `bord`, `v106`, `v136`, `v113`, `v116`, `v025`. Design and identifier fields are retained for audit, weighting and validation only. Do not use child anthropometry, other nutritional scores or post-assessment referrals as predictors.

## Model development

Choose intended geography and holdout before training. Use complete PSUs as validation groups and assert household separation. Learn imputation, encodings, scaling and any tuning within development folds only. Compare an age-based baseline, regularized logistic regression and one shallow XGBoost model. Tune only within development data; reserve the geographic test set for final evaluation.

## Evaluation and reporting

Report cohort flow, missingness, outcome frequency, ROC-AUC, precision-recall performance, sensitivity, specificity, precision, Brier score and calibration curves. Declare decision thresholds on development data. Include survey-weighted results, cluster-aware uncertainty, geographic results and age/sex subgroup results. Evaluate whether any apparent gain would be useful at fixed outreach capacity; do not equate classification accuracy with clinical benefit.

## Reports to generate

- Data-quality report: generated by the supplied audit code after approved data arrive.
- Model-comparison report: generated after model implementation and actual training/evaluation.
- Final academic report: background, methods, actual results, discussion, limitations and reproducibility information.

No sample size, missingness rate, accuracy, feature importance or clinical benefit is known yet. Synthetic test fixtures check software behaviour only and are not study data.

## Implementation update — 29 October 2026

A complete local upload/training/download application is now available in `app.py` and `pipeline.py`; see `README.md`. For raw KR data it implements a conservative co-resident cohort with matching interview/measurement age; for the derived CSV it applies the reduced, explicitly reported eligibility rules described above. Both routes use four separate fitting/calibration/validation/test partitions, fixed model settings, weighted Brier-based selection, and a threshold chosen on validation data. The download contains the exact evaluated model, preprocessing, inference code and report. No refit on test data is performed.

The implementation uses one prespecified group/geographic split rather than the nested development folds envisaged above. It includes approximate stratified PSU-bootstrap intervals; these do not fully account for survey-design or model-selection uncertainty. The field-use and local-validation questions remain open. Automated software checks use synthetic records, including tests for canonical CSV and the derived India KR schema. The supplied `india_kr.csv` has completed a temporary end-to-end compatibility run, but its provenance/codebook and the official raw release remain unverified. No provisional model score from that compatibility run should be presented as a finalized research result.
